# Інтеграція фронтенду з бекендом: що зроблено і що ще треба

Гілка: `feature/frontend-backend-integration`

Фронтенд більше не використовує мок-дані: усі сторінки працюють з FastAPI-бекендом через `frontend/src/app/lib/api.ts`.
Елементи інтерфейсу, яким на бекенді немає відповідника, позначені в UI бейджем **«Скоро» / «Soon»** і перелічені нижче.

---

## 1. Чого немає на бекенді (треба реалізувати)

| # | Функція у фронтенді | Що бракує на бекенді | Як зараз у фронтенді |
|---|---|---|---|
| 1 | **Відновлення пароля** (`/forgot-password` → `/verify` → `/reset`) | Ендпоінти й надсилання email. Фронт уже викликає контракт:<br>`POST /api/auth/password-reset/request {email}`<br>`POST /api/auth/password-reset/verify {email, code}`<br>`POST /api/auth/password-reset/confirm {email, code, new_password}` | Показує повідомлення «Відновлення пароля поки недоступне». Після появи ендпоінтів запрацює без змін у фронті. |
| 2 | **Стрічка сповіщень** (дзвіночок у TopBar) | Модель `Notification` має лише `deadline`, немає API для списку/прочитання | Сповіщення формуються на фронті з реальних даних (бюджет ≥85%/перевищено, дедлайн цілі ≤30 днів, регулярний платіж ≤3 дні) з урахуванням налаштувань сповіщень. «Прочитано» — у localStorage. Див. `hooks/useAlerts.ts`. |
| 3 | **Надсилання email/push** | Налаштування сповіщень зберігаються, але нічого не надсилається | Перемикачі працюють і зберігаються; є підказка, що доставку ще не реалізовано. |
| 4 | **AI-інсайти** | Немає ендпоінта | Замінено на «Інсайти» — правила на реальних даних аналітики (`lib/insights.ts`). |
| 5 | **Іконка та колір цілі** | У `Goal` немає полів `icon`, `color` | Зберігаються в localStorage браузера (`lib/finance.ts → goalAppearance`). Пропозиція: додати nullable-колонки `icon VARCHAR(32)`, `color VARCHAR(16)` у `goals` + у схеми. |
| 6 | **Прив'язка транзакцій до бюджету** | `Transaction` не має `budget_id`; аналітика бюджету рахує **всі** витрати **всіх** учасників | Огляд бюджету показує ці дані як є, з підказкою «Враховано витрати всіх учасників». Пропозиція: `transactions.budget_id` (nullable FK) і фільтр в аналітиці. |
| 7 | **Ліміти по категоріях у бюджеті** | Є лише загальний `limit_amount` | Показується розподіл витрат за категоріями (частка від загальних витрат), без окремих лімітів. |
| 8 | **Номер телефону** у профілі | Немає поля в `User` | Поле вимкнене, бейдж «Скоро». |
| 9 | **Завантаження аватара файлом** | Є лише `avatar_url` (рядок) | Аватар задається посиланням на зображення. |
| 10 | **Активні сесії / відкликання** | JWT без сервера сесій чи blacklist | Показується лише поточна сесія, бейдж «Скоро». |
| 11 | **Оплата підписки** (спосіб оплати, історія платежів) | Немає платіжного провайдера; upgrade/downgrade міняють план одразу | Кнопки оплати вимкнені («Скоро»); зміна плану працює через наявні ендпоінти. |
| 12 | **Тема (темна/авто)**, **звукові ефекти** | — (суто фронтенд) | Вимкнені, «Скоро». Потребує переробки стилів сторінок (зараз жорсткі кольори Tailwind). |
| 13 | **Чеки / OCR** (`/api/files/receipts`) | Бекенд є | У фронтенді немає UI для чеків — можна додати до форми транзакції. |
| 14 | **Текстовий пошук транзакцій** | Немає параметра пошуку в `GET /api/transactions` | Пошук фільтрує вже завантажені транзакції на клієнті. |
| 15 | **Пагінація з загальною кількістю** | Список не повертає `total` | «Завантажити ще» збільшує `limit` (до 1000). |

## 2. Зауваження до логіки бекенду (варто обговорити)

- **Переказ (TRANSFER) збільшує баланс.** `convert_to_user_currency` віднімає лише EXPENSE, тож TRANSFER додається до `capital` як дохід.
- **`PATCH /api/users/me` з `default_currency`** не перераховує `capital` (у `/api/settings/currency` це виправлено, див. нижче). Краще залишити один ендпоінт для зміни валюти.
- **Порівняння «місяць до місяця»** (`/analytics/comparison/period?mode=monthly`) порівнює неповний поточний місяць з повним попереднім — відсотки на початку місяця завжди сильно «мінусові».
- **OAuth-користувачі обходять 2FA**, а пароль-заглушка (`__google_oauth__`) хешується як звичайний пароль.
- **`SessionMiddleware`** з жорстко прописаним секретом у `app.py`; `SECRET_KEY` за замовчуванням — `"secret_key"`. Для прод — обов'язково з `.env`.
- **Обмеження FREE-плану** (50 транзакцій/міс., 3 цілі, 1 бюджет) лише описані в `/settings/subscription`, але ніде не перевіряються.
- Немає міграцій у репозиторії (`alembic/` в `.gitignore`), тож кожен розробник генерує їх сам.

## 3. Що змінено в бекенді в цій гілці

Тільки виправлення, без яких фронт не працював, і невеликі доповнення API:

1. `requirements.txt` — додано відсутні `pyotp`, `qrcode`, `Authlib` (без них бекенд не стартував).
2. `config.py` — CORS для `5173/5174/127.0.0.1`, нова змінна `FRONTEND_URL`.
3. **Баг:** фільтр `?kind=` у `GET /api/transactions` і `/analytics/breakdown/*` завжди повертав 422 (int-enum не парситься з query). Тепер приймає `EXPENSE/INCOME/TRANSFER` або `0/1/2`.
4. **Баг:** `GET /api/transactions/recurring` був недоступний — маршрут `/{tx_id}` перехоплював його. Змінено порядок підключення роутерів в `app.py`.
5. **Баг:** `POST /api/budgets` ігнорував `limit_amount`.
6. **Баг:** `PATCH /api/transactions/{id}` не оновлював баланс (`capital`) при зміні суми/типу/валюти.
7. **Баг:** `PATCH /api/settings/currency` не перераховував баланс у нову валюту.
8. Учасники бюджету: відповідь містить `username` та `email`; додавання за `email` (або `user_id`, як раніше); новий `PATCH /api/budgets/{id}/members/{user_id}` для зміни ролі.
9. OAuth (Google/GitHub): після входу редірект на `{FRONTEND_URL}/oauth/callback#access_token=…&refresh_token=…` замість JSON. Для перевірки потрібні `GOOGLE_CLIENT_ID/SECRET`, `GITHUB_CLIENT_ID/SECRET` у `.env` — без них не тестувалося.
10. `scripts/init_db.py` — створення таблиць без Alembic для локальної розробки.

## 4. Відомі дрібниці фронтенду

- Компоненти shadcn у `components/ui` написані під React 19 (ref як prop), а в проєкті React 18. `Button`, `DialogOverlay`, `AlertDialogOverlay` переведено на `forwardRef`; інші компоненти можуть давати попередження в консолі, якщо їм передати `ref`.
- Немає `favicon.ico` (404 у консолі).
- Бандл > 500 КБ — варто розбити по сторінках (`React.lazy`).
