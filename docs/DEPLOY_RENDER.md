# Deploying to Render + Neon (free tier)

| Part | Where | Config |
|---|---|---|
| Frontend (React) | Render **Static Site** `financehub` | `render.yaml` |
| Backend (FastAPI, Docker) | Render **Web Service** `financehub-api` (free) | `render.yaml`, `backend/Dockerfile` |
| Database (Postgres) | **Neon** free project | `DATABASE_URL` |
| Receipt files | Stored **in the Neon database**, max 5 per user, 20 MB each | `FILE_STORAGE=database` |

The static site rewrites `/api/*` to the backend, so the browser keeps talking to one origin,
just like `frontend/nginx.conf` does in docker-compose. nginx itself is not deployed.

Free-tier trade-offs: the backend sleeps after ~15 min without traffic (first request then
takes 30–60 s), it has ~512 MB RAM / 0.1 CPU (receipt OCR is slow), and its disk is wiped on
every deploy, restart and wake-up from sleep — hence receipt files are kept in Postgres
(`receipt_files` table) instead of on disk. Neon pauses an idle database too; the first
query after a pause takes a second or two.

Storage budget: Neon's free plan has 0.5 GB. Each user can keep at most 5 receipts
(`MAX_RECEIPTS_PER_USER`), up to 20 MB each (`MAX_UPLOAD_SIZE_MB`); phone photos and PDF
receipts are usually 0.2–3 MB. Lower `MAX_UPLOAD_SIZE_MB` if storage runs low. A 6th upload is
rejected with HTTP 409 until the user deletes one.

## 1. Neon (database)

1. Sign up at <https://neon.tech> → create a project (pick the region closest to your Render region, e.g. Frankfurt ↔ `aws-eu-central-1`).
2. **Dashboard → Connect**: turn **Connection pooling off** and copy the connection string:
   `postgresql://user:password@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`
   Use the direct (non-pooled) string: asyncpg's prepared statements don't mix well with the PgBouncer pooler.
   The backend converts `sslmode`/`channel_binding` for asyncpg itself (`src/config.py`).

Tables are created on every backend start (`scripts/init_db`), no manual migration needed.

## 2. Render (backend + frontend)

1. Push this branch to GitHub (Render deploys from the repo).
2. <https://dashboard.render.com> → **New → Blueprint** → pick the repository; Render reads `render.yaml`.
3. Fill in the prompted values:
   - `DATABASE_URL`: the Neon string from step 1
   - `GOOGLE_*` / `GITHUB_*`: leave empty unless you use OAuth sign-in
   `SECRET_KEY` and `SESSION_SECRET` are generated by Render.
4. **Apply**. The first backend build takes a few minutes (Tesseract + Python packages).
5. **Check the URLs.** If `financehub` / `financehub-api` were already taken on onrender.com,
   Render gives the services different URLs. Then update in `render.yaml` (or the dashboard):
   `FRONTEND_URL`, `WEBAUTHN_RP_ID`, `PUBLIC_API_URL` (backend); `VITE_BACKEND_URL` and the `/api/*` rewrite (frontend) — and redeploy.
6. Open `https://financehub.onrender.com`, register, log in.
   Backend health: `https://financehub-api.onrender.com/health/` · Swagger: `/docs`.

## OAuth sign-in (optional)

Register these callback URLs with the providers, then set the client id/secret on the backend service:

- Google: `https://financehub-api.onrender.com/api/auth/google/callback`
  (and `/api/calendar/google/callback` if you use calendar export)
- GitHub: `https://financehub-api.onrender.com/api/auth/github/callback`

## Custom domain (optional)

Add it to the **static site** (Settings → Custom Domains; HTTPS is automatic), then set
`FRONTEND_URL=https://your.domain` and `WEBAUTHN_RP_ID=your.domain` on the backend.
Passkeys are bound to `WEBAUTHN_RP_ID`: pick the final domain before users register passkeys.

## Troubleshooting

- **Backend fails at start with "Refusing to start with APP_ENV=production"**: a secret is missing or shorter than 32 chars.
- **API calls return 404/HTML or POSTs fail through the rewrite**: as a fallback, call the backend directly — set
  `VITE_API_URL=https://financehub-api.onrender.com/api` on the static site and redeploy it
  (CORS already allows `FRONTEND_URL`).
- **First request very slow**: the free backend was asleep; that's expected. An uptime pinger hitting `/health/`
  every 10 min keeps it awake, but uses up most of the 750 free instance hours per month.
- **Logs**: Render dashboard → service → Logs.
